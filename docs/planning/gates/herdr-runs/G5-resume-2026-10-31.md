## What it shows

- **Registration at start:** the `SessionStart` hook and the shim paired, and each run was one bound session.
- **Deregistration at exit ([SC-ID-155]):** after each run ended, no session was listed.
- **The C4 §6 rule, live:** a resumed or continued Claude session is a new OAC session.
  - At Claude Code `2.1.312`, print mode, `--resume` and `--continue` both **kept** run A's Claude session id.
  - OAC still gave each run a new session id.
  - This is the case `adapters/claude/tests/registration.rs` `the_hook_session_id_registers_the_session_across_start_resume_and_exit` models with its fake harness: same hook `session_id`, new process, new OAC session.
- The daemon accepted six connections and saw six end: a shim and a hook handler per run (`scenarioData.daemon`).

- The twin refusal ([SC-ID-132], two live processes reporting one Claude session id). That is covered by the fake-harness test only.
- `/clear` mid-session, which needs an interactive session.
- Any platform other than Windows.
